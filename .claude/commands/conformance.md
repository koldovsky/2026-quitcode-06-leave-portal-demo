Перебудуй матрицю відповідності `docs/conformance.md` для цього форку. Обмеження (якщо задано): $ARGUMENTS

Межі: специфікації тільки читаєш — **не змінюй** `product/**`, `openspec/specs/**`, `openspec/changes/**`.
Пишеш лише в `docs/conformance.md`. Тести не вигадуєш і не позначаєш «реалізовано» без тесту.

1. Збери всі AC ID з назв `#### Scenario:` в `openspec/specs/**/spec.md` (без секцій `## REMOVED Requirements`).
   Версію специфікації візьми з `.spec-source` (`version:`).
2. Для кожного AC знайди:
   - **тест** — непропущений `test()`/`it()` у `src/**` або `tests/**`, у назві якого є цей ID
     (закоментовані, `.skip`/`.todo`/`.fixme`/`.fails`/`.skipIf` і тести в `describe.skip` не рахуються;
     `it.each`/`test.for`/`.concurrent`/`.runIf` — рахуються);
   - **код** — файл і функцію, що реалізують поведінку (server action, сторінка, міграція з політикою RLS);
     шукай від тесту (що він імпортує / яку сторінку відкриває) і за ключовими словами сценарію.
3. Перебудуй таблицю, зберігаючи шапку файлу й коментарі. Один рядок на AC, у порядку специфікації:

   `| AC-… | що перевіряє (коротко, своїми словами) | \`шлях/до/коду.ts\` | \`шлях/до/тесту.test.ts\` | статус |`

   Статус — лише один із двох, дослівно (без «частково», «?» тощо — інакше BAD-STATUS):
   - `реалізовано` — є і код, і непропущений тест з ID у назві;
   - `відкладено (причина)` — причина конкретна: «чекаємо відповідь PM на Q3 (#12)», «не входить у зріз 1».
   Наявні рядки «відкладено (…)» з причиною залиш, якщо тест так і не з'явився.
4. Запусти `npm run ac:coverage` і покажи результат. Якщо FAIL — поясни кожен рядок
   (NO-ROW / MISSING / ORPHAN / BAD-STATUS) і запропонуй, що зробити: дописати тест, змінити статус,
   прибрати ID з назви тесту, якщо AC видалено зі спеки.
5. Підсумок для PR: скільки AC «реалізовано» / «відкладено», які AC без тесту, які тести посилаються на
   неіснуючі AC. Нагадай: оновлена матриця йде в тому самому PR, що й код.

`/opsx:verify` і цей звіт — поради; ворота — детерміновані перевірки CI (`npm run ac:coverage`, `npm test`).
