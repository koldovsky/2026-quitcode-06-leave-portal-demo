# Технічні рішення (ADR)

Тут розробник фіксує рішення, які специфікація PM свідомо залишає відкритими: модель даних, політики RLS,
структура сторінок, бібліотеки. Продуктові рішення (що робить система) — не тут, а в `product/decisions.md` upstream.

- Один файл — одне рішення: `docs/decisions/NNNN-коротка-назва.md` (`0001-model-leave-entries.md`).
- 1–2 сторінки. Старі рішення не видаляємо: нове рішення отримує статус «замінює NNNN», старе — «замінено NNNN».
- Посилайтесь на AC ID, яких стосується рішення.

## Шаблон

```markdown
# NNNN. <Назва рішення>

- Статус: запропоновано | прийнято | застаріло | замінює NNNN | замінено NNNN
- Дата: 2026-10-14
- AC: AC-…-01, AC-…-02

## Контекст

Яку проблему розв'язуємо, які обмеження (специфікація, стек, тарифи), що відомо зараз.

## Рішення

Що обрали — конкретно (таблиці, політики, сторінки, бібліотеки).

## Розглянуті варіанти

- Варіант A — чому ні.
- Варіант B — чому ні.

## Наслідки

Що стає простішим, що складнішим; що доведеться змінити, якщо специфікація зміниться.
```
