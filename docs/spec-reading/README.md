# Журнали читання специфікації

Кожен розробник веде **свій** файл у цій теці: `docs/spec-reading/<login>.md`, де `<login>` — ваш GitHub-логін
(`gh api user -q .login`). Окремі файли — щоб паралельні PR-и не конфліктували в одному журналі.

- Скіл `spec-clarify` створює файл за структурою нижче й записує туди скан за таксономією та питання.
- Питання до PM — issues `spec-question` у цьому ж репозиторії. Перед новим issue перегляньте наявні (і журнали колег):
  якщо питання вже є — коментар із новим випадком у тому issue, а не дублікат.
- Комітимо журнал PR-ом типу «Онбординг» (або разом із задачею, яку він стосується); рев'ю — колега.
- Для PM це матеріал підсумкової нотатки: де одна й та сама спека прочиталась по-різному.
